Four browser surfaces jsdom does not provide, each needing a stub built from what the component actually calls:

- Web Audio. `window.AudioContext` does not exist under jsdom. Install a constructor stub whose instances expose `decodeAudioData` resolving a fake `AudioBuffer` and `createBufferSource` returning an object with the connect/start/stop shape the preview path uses. The fake buffer needs `duration`, `length`, `sampleRate`, `numberOfChannels`, and a `getChannelData` returning a `Float32Array`; the amplitude reducer and the RMS reducer both walk that array, so give it real sample values rather than an empty one.
- File bytes. The decode effect calls `file.arrayBuffer()`. Construct the `File` from a real `ArrayBuffer` so this resolves; if the runtime's `File` lacks `arrayBuffer`, attach one rather than changing the component.
- Canvas. `HTMLCanvasElement.prototype.getContext` returns null under jsdom without the native `canvas` package, which is deliberately not installed. Spy on it and return a minimal fake 2D context carrying only the methods and settable properties the waveform block uses; read the draw block and enumerate them from the source rather than adding methods speculatively.
- Computed style. `themeColor` reads a CSS custom property and falls back to a literal when it is empty. jsdom returns empty, so the fallback is what runs; that is fine and needs no stub, but do not assert on colour values.

Interaction depth (D-04). The lane exists so a retune opens on what it is retuning. Assert that, at every outcome `seedTrimWindow` can produce, by driving the same seed and the same decoded duration through `seedTrimWindow` in the test and asserting the editor's rendered window matches:

1. `fit: 'none'` - no seed. The editor opens on the whole clip at unity gain.
2. `fit: 'exact'` - a seed that fits inside the decoded duration. The editor opens on exactly that window and that gain.
3. `fit: 'clamped'` - a seed whose end runs past the decoded duration. The editor opens clamped to the clip, not on the out-of-range value. This is the upper threshold.
4. `fit: 'dropped'` - a seed whose window is narrower than `MIN_WINDOW_MS`. The editor opens on the whole clip. This is the lower threshold.

Also assert the `initialEdits.loop` display branches render the on and off forms, and assert `onChange` was called with edits carrying the fitted window rather than the raw seed. Derive every expected number by calling `seedTrimWindow` in the test with the same inputs; do not hand-type millisecond literals, so the test cannot drift from the function it is checking.
