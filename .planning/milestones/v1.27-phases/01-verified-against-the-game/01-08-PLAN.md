<objective>
Move the phase's completion gate off a Deadlock session and onto the running app.

Purpose: 01-06 scaffolded 41 rows on the premise that "no agent can run Deadlock and no headless process can produce an fps number" (D-09). The first half stands. The second half does not, and neither does the assumption behind most of the sweep. `scripts/dev-driver.mjs` reaches a live renderer over CDP, and that renderer exposes 266 `window.electronAPI` methods including `foundry.forge`, `foundry.forgeInstall`, `foundry.auditionSourceClip`, `mergeMods`, `analyzeMerge`, `enableMod`, and `disableMod` (verified 2026-08-06 against a slot-3 dev build). Every write path the sweep cares about is drivable from a script.

What that buys and what it does not: an app-tier check proves Grimoire wrote the intended entry path with the intended bytes into the intended VPK. It does not prove the Source 2 engine loads that VPK, that the sound is audible, or that the minimap draws the portrait the label claims. Those stay engine facts. The user's standing position is that the in-game side works, so this plan makes the engine rows deferrable with a reason rather than blocking, and makes everything else automatic.

Output: a tiered record, a runner that settles 23 rows unattended, and a `--strict` gate that can reach 0 without anyone starting the game.
</objective>

Write `scripts/verify-in-app.mjs`: a runner that drives one dev slot through the 23 app-tier rows and writes each verdict back into the record.

Shape it like the repo's other scripts: pure exported functions plus a CLI entry guarded by `import.meta.url` against `process.argv[1]`, exit code rather than throw, same house style as `scripts/check-verification-record.mjs`.

Slot handling is a safety gate, not a convenience. The runner reads `GRIMOIRE_DEV_SLOT` and refuses to run when it is unset, `0`, or a slot whose `window.__GRIMOIRE_DEV_SLOT` does not match what was asked for. It prints the slot it is about to write through and what it will touch before the first mutation. The reason is in `CLAUDE.md`: slots isolate userData but share one game install, so two slots toggling mods are writing to the same addons directory.

Each row is one exported check function taking a driver handle and returning `{ id, verdict, evidence }`. The evidence string is what lands in the record's Evidence cell, so it names what ran and what came back, not "ok".

The assertions, by row:

- IG-01: stage one sound edit and one texture edit through `foundry.swapSound` and `foundry.replaceTexture`, read the combined tray, call `foundry.forge`, then open the resulting VPK and assert both entry paths are present and that each entry's bytes equal the staged source's bytes. Two paths, two byte comparisons, one VPK.
- IG-02: invoke the export path with the save dialog cancelled, then assert that `getMods()` is identical to a snapshot taken beforehand, that the staged tray still lists both edits, and that no new file appeared at the export target. Drive the cancellation the way the app's own dialog wrapper allows; if `showSaveDialog` cannot be made to return a cancellation from the renderer, record IG-02 as `blocked` with that as the reason rather than faking it.
- IG-03: `foundry.forgeInstall` one edit, then assert `getMods()` gained exactly one entry, that it is enabled, and that its VPK exists in the addons directory and holds the expected entry.
- IG-04: occupy every slot the allocator would use, attempt a forge-install, assert it reports failure and that `getMods()` and the addons directory both match the pre-attempt snapshot exactly.
- IG-05: make the metadata sidecar unwritable, attempt a forge-install, assert the same no-orphan invariant plus that no VPK was left behind.
- IG-06: install two mods that write the same entry path, call `analyzeMerge` and record the reviewed source order verbatim, call `mergeMods`, then read the contested entry out of the merged VPK and assert its bytes equal the winner the review named. This is a stronger check than the in-game one it replaces: it compares bytes rather than an eyeball on a texture.
- IG-07: `foundry.auditionSourceClip` for an installed mod's sound entry, and assert the audition bytes equal the bytes at that entry inside the installed VPK.
- IG-08: forge the same swap twice from the same source and assert the two VPKs' entry bytes are identical at the swapped path. Compare entry bytes, not whole-file bytes: an archive can differ in ordering or padding without the content differing.
- IG-09 through IG-20, the twelve-cell matrix. Each cell is one of four kinds against one of three scopes (hero, voice, global):
  - downloaded third-party mod: the installed VPK holds the replacement at the expected entry path.
  - forged mod: same assertion against a Foundry-forged VPK.
  - disabled mod: after `disableMod`, assert the mod's VPK is no longer in the enabled set the launch path would mount, and that no enabled VPK still claims that entry path.
  - multi-clip pool: call the pool's own selection path enough times to be confident, and assert more than one distinct clip came back. State the iteration count in the evidence so the claim is reproducible.
- RP-01: open Seven's Locker hero page with rigged on, sample the world matrices of the gun and headgear meshes over about two seconds, and assert they change and that they change together with the body's root bone rather than staying static. This replaces "watch it and see", and it is a stronger claim.
- RP-02: capture screenshots at a fixed set of orbit angles with rigged on and rigged off, and store them as evidence files. Do not assert a verdict on the rim automatically. Record the verdict as the reader's, with the screenshot paths as evidence. This is the one app-tier row where the eye is still the instrument; say so in the row rather than pretending an assertion exists.
- RP-03: is 01-07's, not this plan's. The runner exposes the frame-time helper 01-07 calls, and leaves RP-03's verdict alone.

Write results back into `docs/ingame-verification-record.md` by ID, filling only the Verdict and Evidence cells of rows the run actually settled. Never touch a row the run did not attempt, never touch an engine-tier row, and never overwrite a non-blank verdict without `--force`.

Add `--dry-run` that prints the plan of what each check would do and mutates nothing. That is the mode a reviewer runs first.
