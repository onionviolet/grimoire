<objective>
Make the catalog's declared kinds visible in the UI (grouped rows per 06-UI-SPEC.md), and turn the browser's deliberately small control set from an undocumented gap into a written decision (REQ-browser-navigation-gaps).

Purpose: D-04 says an entry declares what kind of thing it is so the UI can group them. Until it does, the kind is invisible to the person the grouping is for. And REQ-browser-navigation-gaps exists for exactly one reason: so the missing controls are a recorded decision rather than something nobody noticed.

Output: kind-grouped destination rows with tested grouping logic, and `docs/browser-scope-boundary.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| destination label to rendered markup | Labels are app-authored constants, not user or page supplied, so they are trusted text; the boundary matters only if a future change lets a user add a destination |
| nsfw preference to what is rendered | A user preference decides whether a destination is reachable at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-20 | Tampering | nsfw filtering in the grouped render | medium | mitigate | `visibleDestinations` is applied before `groupDestinationsByKind`, so a hidden entry cannot reappear through a group that skipped the filter. Unit tested for the hide mode across all groups. |
| T-06-21 | Spoofing | group headers implying capability | medium | mitigate | The Tools group is the only accented group and the only kind the download capture gate honours, so the visual signal and the capability agree. A destination cannot look like a tool without being one, because both read the same `kind` field. |
| T-06-22 | Elevation of Privilege | new browser controls | medium | mitigate | The recorded boundary makes adding a control a documented decision. The specific control this phase could have implied, a download manager, is named in the record as deliberately absent, so a later contributor does not build one to match a UI affordance that does not exist. |
| T-06-23 | Denial of Service | a very long destination label | low | accept | Labels are app-authored constants. A long one wraps rather than truncating or clipping, and the 900 pixel viewport check bounds the worst case. No user or page supplied text reaches this row. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No packages are added by this plan. RESEARCH.md's Package Legitimacy Audit records zero new dependencies, so there is no install task to gate. |
</threat_model>
