<objective>
Decide the social service question in writing, prove the client is already honest about a dormant one, and settle the terms-of-service gate drift.

Purpose: a shipped installer bakes `https://grimoire-social.slusheliott.workers.dev` into every packaged build, which is the upstream project's production Worker. Per D-01 that stays, and the deliverable is that the choice is decided and written down. RESEARCH.md found the client already degrades correctly against a service that does not run the revalidation cron, so this plan verifies that claim rather than writing new code for it.

Output: ADR-018, a small guard test, a typecheck run against the sibling as CI actually resolves it, and a decided answer on the terms gate.

## Scope this plan deliberately does not take, per D-01

No fork of `grimoire-social` to `onionviolet`. No repointing of `.github/workflows/ci.yml` line 30, `.github/workflows/release.yml` line 56, or `scripts/check-sibling-repos.mjs` line 27. No push of the three unpushed sibling commits. No application of migration 0005. No Worker deploy. Each of these is recorded in ADR-018 as a considered alternative rather than left as an unexplained absence.

Schema-push gate: skipped, and here is the one-line reason. The only migration in scope anywhere near this phase is `migrations/0005_revalidation_and_views.sql` in the sibling repository, which D-01 explicitly rules out applying, so there is no in-scope schema change and no push command to run.

Per Pitfall 4 in RESEARCH.md, this plan does NOT write new gating logic for the availability badge or the view count. `resolveModsAvailability` and the `viewCount !== undefined` gate already do it correctly, with code comments explaining why. Task 1 proves that and stops.

## Flagged planner assumptions (edge probe, unresolved)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| packaged client to third-party Worker | Every shipped build sends publish, browse, and like traffic to a service this fork does not operate. |
| main process to renderer | The social session token lives in the main process behind `safeStorage` and must never reach the renderer. |
| CI runner to sibling repository | `.github/workflows/ci.yml` checks out `Slush97/grimoire-social` at a moving branch ref on every run. |
| local disk to consent record | Terms acceptance lives in `localStorage`, which is per-machine and user-clearable. |
