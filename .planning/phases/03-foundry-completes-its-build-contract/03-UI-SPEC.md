# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Grimoire ships a mature, hand-rolled design system that predates and substitutes for shadcn. No `components.json` exists and none should be added: `src/components/common/ui.tsx`, `forms.tsx`, `PageComponents.tsx`, `Modal.tsx`, `menu.tsx` are the primitive layer, and `docs/ui-conventions.md` is the binding house style ("reach for an existing primitive before writing markup"). Initializing shadcn here would introduce a second, conflicting component vocabulary into a project with an established one. |
| Preset | not applicable |
| Component library | custom (`src/components/common/*`), no Radix/base-ui dependency |
| Icon library | lucide-react `^0.562.0` |
| Font | Body: Radiance (400/600/700 available). Display/headings: Reaver (600 only — never apply a heavier weight, `.font-mod-title { font-synthesis: none }` exists specifically to stop faux-bold blur). Branding-only: ValvePulp (700), American Captain (400) — not used by this phase's surfaces. |

**Scope note:** this phase adds no new page or route. Every element below is a small addition to three existing, already-styled surfaces (`HeroColorPicker.tsx`/`HeroEffectsPanel.tsx`, `FoundryBuildTray.tsx`/`MyChanges.tsx`/`changeList.ts`, `HeroWorkshop.tsx`/`SoundBrowse.tsx`). The contract below is deliberately narrow: it declares how the *new* recolor-staging and sound-shuffle elements must look and read, using the app's existing tokens and primitives rather than inventing new ones. It does not restate the whole app's design system.

## Spacing Scale

Declared values (the project's actual Tailwind scale, multiples of 4 with the noted half-step exception):

| Token | Value | Usage in this phase |
|-------|-------|-----|
| 2xs | 2px (`py-0.5`) | Tag/Badge vertical padding — reuse `Tag`/`Badge` as-is, do not hand-roll |
| xs | 4px (`gap-1`, `px-1.5`≈6px) | Icon-to-label gaps on the new "Open in Sound Locker" link and the recolor kind `Tag`, matching `ExternalLink size={11}` + text pattern already in `MyChanges.tsx:305-317` |
| sm | 8px (`gap-2`, `px-2`) | Spacing between the sound-shuffle toggle button and its row's other controls in `SoundRow` |
| md | 16px (`p-4`, `gap-4`) | Padding inside any new inline row/section wrapping the shuffle toggle in `HeroWorkshop.tsx` |
| lg | 24px (`p-6`) | Not newly introduced by this phase — existing `Card`/panel padding this phase's elements sit inside |

Exceptions: the codebase's HUD-styled compact chrome (`Tag`, `IconButton` `sm` size, the existing "Open in Sound Locker" link) already uses half-steps below 4px (`py-0.5` = 2px, `gap-1.5` = 6px). This phase's new elements must match those exact existing classes rather than round to the nearest 4/8 multiple — consistency with the immediate neighboring control outranks the abstract 8-point scale here.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular, Radiance) | 1.5 |
| Label | 12px (`text-xs`) | 500 (`font-medium`, Radiance) | 1.2 |

Notes specific to this phase:
- The new inline "Open in Sound Locker" link and the recolor `Tag` reuse the codebase's existing **11px** (`text-[11px]`) compact-link convention verbatim (`MyChanges.tsx:313`) — this is an intentional, already-established exception one step below the Label row, not a new size to add to the app's scale.
- Display (30px/Reaver) is listed for completeness only; this phase introduces no new page-level heading and must not add one.
- Any new copy on the Abilities tab distinguishing "stages" from Body+Gun's "applies immediately" (see Copywriting Contract) uses the **Body** row (`text-xs text-text-secondary`, matching `HeroEffectsPanel`'s existing description-line convention), not a new heading.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-bg-primary` `#0f0f0f` | App background behind every surface this phase touches |
| Secondary (30%) | `bg-bg-secondary` `#1a1a1a` / `bg-bg-tertiary` `#242424` | Card/panel bodies (`HeroEffectsPanel`, `FoundryBuildTray` rows), the sound-shuffle toggle's unpressed track (`ToggleIndicator`'s existing `bg-white/[0.16]`) |
| Accent (10%) | `bg-accent` / `text-accent` / `border-accent` `#f97316` | Reserved for: the recolor kind's `Palette` icon and `Tag` (tone `accent`), the sound-shuffle toggle's **pressed** state only (reuses the existing `aria-pressed` `Shuffle`-icon button styling from `HeroSkinsPanel.tsx`), the "Stage" button's existing `primary` variant border/fill (unchanged from today's `Button` component), and the focus ring (`focus-visible:ring-accent`) on every new interactive element |
| Destructive | `state-danger` `#f87171` | Not introduced by this phase — no new destructive action ships here. If a future revert-staged-recolor control is added, it must use `Button variant="danger"` or `Tag tone="danger"`, never a raw red |

Accent reserved for (explicit list, nothing else): the recolor `Tag`'s icon and border, the sound-shuffle toggle button's pressed/active visual state, the "Stage" button's existing primary-variant treatment (already accent-bordered today, unchanged), and focus-visible rings. Body text, descriptions, and the Body+Gun tab's unrelated immediate-apply button stay on `text-text-primary`/`text-text-secondary` — accent must not bleed into either.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (recolor staging, Abilities tab only) | Replace the four existing mode-specific labels (`locker.colors.applyColor` "Apply colour", `applyRainbow` "Apply rainbow", `applyGradient` "Apply gradient", `applyTrippy` "Apply trippy VFX") with **"Stage colour"**, **"Stage rainbow"**, **"Stage gradient"**, **"Stage trippy VFX"**. "Stage" is the house verb for this exact action already established by `foundry.workshop.stagedEdits`/`stagedEditsEmpty` ("Stage an edit, then review it in the Build tray") — do not introduce a synonym ("Queue", "Add", "Save") |
| Staged-status line (replaces `locker.colors.appliedStatus`/`noRecolorApplied` on the Abilities tab) | **"Staged, not yet forged"** when a recolor edit is pending; **"Not staged"** when none is. Do not reuse the word "Applied" here — D-01 deliberately changes the interaction model from immediate-apply to staged, and carrying over "Applied" language would misrepresent that nothing has been written yet |
| Distinguishing caption (Abilities tab, placed under the new Stage button) | **"This stages into the Foundry build tray. It won't take effect until you forge."** |
| Distinguishing caption (Body+Gun tab, `TrippySkinPanel` — unchanged behavior, new caption so the two tabs don't read as inconsistent) | **"This applies immediately and doesn't go through the build tray."** |
| Recolor build-tray label (kind tag, reuses existing key) | Reuse `foundry.subtools.recolor` = **"Recolor"** verbatim as the kind label wherever `entry.kind === 'sound' ? 'Sound' : 'Texture'`-style ternaries widen to a third branch (`MyChanges.tsx:333`, `changeList.ts:160`) — do not invent a new string for the same concept |
| Recolor collision/inspection error (staging-time, mirrors `SoundBrowse.tsx`'s existing sound-staging error verbatim pattern) | **"Cannot stage this recolor while {{mods}} cannot be inspected. Resolve those VPKs and try again."** |
| Recolor layering-over-enabled-owner confirmation (mirrors `SoundBrowse.tsx:1204`'s existing pattern) | **"These installed mods already provide this recolor and are enabled. Staging adds a separate managed replacement; nothing is removed."** |
| Staging-in-progress state (new — the async bake+entry-discovery step, see UI Considerations) | Button shows `Button isLoading` spinner state with label **"Staging…"** in place of the mode-specific "Stage {{mode}}" label while `prepareRecolorStagedEdit` awaits main |
| Sound-shuffle toggle (Foundry, per-row) | Reuse `locker.randomize.addToShuffle` / `locker.randomize.removeFromShuffle` (`"Add {{name}} to shuffle"` / `"Remove {{name}} from shuffle"`, both already generic and hero-name-parameterized) verbatim — no new key |
| Foundry → Locker pool link (per-hero, sound shuffle) | Reuse the exact existing string and pattern from `foundry.myChanges.openInSoundLocker` = **"Open in Sound Locker"** with the `ExternalLink` icon at `size={11}`, `text-[11px] font-normal text-text-secondary hover:text-text-primary`. Navigate to the already-documented contract string `/locker/sounds?hero=<display name>` (`lockerMode.ts:61-66`) — do not invent new copy or a new route for the same destination |
| Empty state (sound-shuffle row) | None needed. Per D-11, the toggle row must not render at all when a hero has zero sound-swap mods — this is an absence, not an empty state banner. Do not add "No sounds to shuffle yet" copy here |
| Destructive confirmation | Not applicable — this phase ships no new destructive action |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).

Applicable state considerations resolved: 5 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Recolor "Stage" button, Abilities tab | 🧪 backstop | `prepareRecolorStagedEdit` is async (bakes + lists a VPK before staging, per RESEARCH.md Pattern 1) and may be slow for VFX-heavy heroes (Assumptions Log A1). The button must enter `Button isLoading` with "Staging…" copy for the duration; no measured latency exists yet, so this is a backstop until a UAT pass confirms the spinner actually covers the real wait |
| error | Recolor staging, unreadable-mod inspection failure | ✅ covered | Exact copy specified above, mirroring `SoundBrowse.tsx`'s live "Cannot stage this sound while {{mods}} cannot be inspected" pattern — the mechanism (`visualEdits.ts`'s `inspect`/`confirm`) already exists and is reused unchanged |
| populated (collision) | Recolor staging over an already-enabled same-path owner | ✅ covered | Confirmation copy specified above, mirroring `SoundBrowse.tsx:1204`'s existing conflict-preflight string exactly |
| zero-one-many | Sound-shuffle toggle row, per hero | ✅ covered | Zero sound-swap mods for a hero → row does not render (D-11's `.filter()` behavior). One or many → one toggle button per sound-swap mod, matching how `HeroSkinsPanel.tsx` already renders one per skin group |
| partial | `HeroEffectsPanel`'s Abilities tab (staged) vs Body+Gun tab (immediate) coexisting in one mounted panel | ✅ covered | Distinguishing captions specified above for both tabs (Pitfall 4) — this is the state-coverage fix for the exact ambiguity RESEARCH.md flags |
| long-text | Hero display name in the "Open in Sound Locker" link's target hero, and in `addToShuffle`/`removeFromShuffle`'s `{{name}}` interpolation | 🧪 backstop | Existing i18n keys already interpolate hero name without a declared truncation strategy anywhere else in the codebase (`MyChanges.tsx`'s equivalent link has the same property); no hero name in the current roster is long enough to overflow the `text-[11px]` link, but no explicit `truncate` class exists either — carry the existing (unverified) assumption forward rather than adding new handling this phase didn't ask for |
| overflow | Multiple sound-shuffle toggle rows stacking under one hero in `SoundBrowse.tsx` | ✅ covered | Each row is a single inline button appended to the existing `SoundRow` layout (`gap-2` per the Spacing Scale above); no new wrapping/scrolling container is introduced, so overflow behavior is inherited from `SoundRow`'s existing flex layout unchanged |
