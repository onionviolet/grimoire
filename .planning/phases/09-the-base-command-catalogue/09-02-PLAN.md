  <action>
Extend `electron/main/services/chatWheel.test.ts` with two describe blocks, reusing the existing hoisted harness and mocks; import `readChatWheelStarter` and `readChatWheelVpk` alongside `validateChatWheelYaml`.

For starter coverage: build a fresh `mkdtempSync` app path per test (the existing pattern), create `resources/chatlane/starter.yml` with known multi-line content including a comment line, and assert the resolved string equals it exactly. For the missing-template case, point `harness.appPath` at a directory with no `resources/chatlane` and assert the rejection message contains `starter.yml`.

For read coverage, three fixture requirements the guards impose (all verified against chatWheel.ts):

1. The converter binary stub must exist on disk. `readChatWheelVpk` calls `chatLaneBinaryPath()` (lines 9-15), which throws `Chat Wheel converter is unavailable` unless `<appPath>/resources/chatlane/ChatLane[.exe]` exists. Replicate the validate test's fixture setup (test lines 31-33): fresh `mkdtempSync` app path, `mkdirSync` of `resources/chatlane`, write the platform-named stub file.
2. The happy-path and fail-path tests need a real `.vpk` file on disk: line 40 requires both the `.vpk` suffix and `existsSync`. Write a dummy file at `join(dir, 'wheel.vpk')`; the service only stats it, contents are irrelevant.
3. Do all of this, plus resetting `mode`, `outputText`, `calls`, and `harness.appPath`, in a `beforeEach` for the read describe block. `harness.appPath` is module-level mutable state; without its own reset the block silently depends on declaration order.

Make the spawn stub's behaviour steerable per test. The current stub always writes `args[1]` and emits close(0); extend the hoisted harness with a `mode` field (`'ok' | 'fail'`) and an `outputText` field so a test can request a failing run. In 'ok' mode write a known YAML string (not just 'vpk') to args[1] so the happy-path test can assert content equality. In 'fail' mode emit `outputText` on the stderr emitter first (when non-empty), then `close(1)`, and write nothing. Typing trap: the stub builds `const child = new EventEmitter()` and `Object.assign`s the stdout/stderr emitters on, discarding the return value, so `child.stderr` does not typecheck. Hold the emitters in local `const` bindings (`const stderr = new EventEmitter()`) before the assign and emit on those; the plan's `tsc -b` gate fails otherwise. Keep the default 'ok' so the existing validate tests pass unchanged.

Temp-dir cleanup assertions: capture `args[1]` from `harness.calls`, then after the call assert `existsSync(dirname(args[1]))` is false. For the extension and missing-file rejections assert only that `harness.calls` stayed empty: no temp dir ever exists there, because the guard at line 40 precedes the `mkdtemp` at line 41, so do not attempt a leak assertion (and do not reach for the roundtrip suite's prefix-scan).

Do not touch production code. Do not add an `ipcMain` mock: the handlers are one-line delegations and the repo has no IPC-handler test precedent (09-RESEARCH 2.4).
  </action>
