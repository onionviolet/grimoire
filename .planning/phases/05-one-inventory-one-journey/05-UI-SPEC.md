Every table row below therefore declares tokens only for the **genuinely new or copy-corrected** elements identified above (E1-E8). It does not restate colors/type/spacing for `GlobalSoundShelf`, `HeroCardPicker`'s existing family cards, or the shared inventory models, which are load-bearing and unchanged by this phase — an implementer should read them at the file:line references above and leave the working parts alone.

**Visual hierarchy:**
- **Global drill-in section selector (E1):** becomes the primary navigational decision at the top of the left rail, visually equal in weight to the existing `Visuals`/`Sounds` two-tab treatment it extends (same `SegmentedControl`-class treatment, now three options) — it must not read as a third, subordinate control bolted beside the existing two.
- **Rail category rows (E2):** unchanged treatment for the rows that remain; the "filtered to zero" reset state that replaces a fully-hidden empty set is secondary chrome (small, muted) so it never competes with populated rows for attention.
- **Randomization scope labels (E3):** subordinate captions beneath/beside each existing toggle, not new controls — `text-text-secondary`, never accent, so the two toggles keep their existing visual weight and only their meaning gets clarified.
- **Unresolved-codename indicator (E4):** a neutral `Tag` (never accent, never danger) wherever a family or catalog row cannot be placed — it reports an honest gap, not a warning of harm.
- **Undo toast (E6):** reuses the existing `ToastStack` bottom-center treatment verbatim; no new toast visual language.

| partial | ✅ covered | A family or catalog view can have some resolved and some unresolved members simultaneously; each unresolved member gets its own tag, and the explanatory hint renders once per unresolved group (not once per tag), per the Copywriting Contract's "shown once per unresolved group, not per row" |
| overflow | ✅ covered | Tag is a single short `Tag` primitive instance; multiple tags wrap within their existing grid/list container like any other tag in the app |
| zero-one-many | ✅ covered | Zero, one, or many unresolved codenames can appear per view; each gets an independent tag, matching the existing many-tags-per-row pattern already used elsewhere (e.g. sound category chips) |
| long-text | n/a | The tag's visible text is the fixed word "Unresolved"; the raw codename lives in a `title` attribute, not rendered layout, so codename length cannot affect the tag's width |
