<objective>
Make ROADMAP success criterion 4 checkable instead of asserted: extract the `will-attach-webview` hardening body into one fork-only, unit-tested function, and pin the browser partition's permission floor with its own test.

Purpose: the phase's whole premise is that the download path can change without weakening the guest. Today that claim rests on a comment and on nobody editing the block. A test that fails when any one of the nine invariants is dropped turns the claim into a fact, and moving the logic into a fork-only module also shrinks the fork's edit to the shared `electron/main/index.ts` rather than growing it.

Output: `webviewHardening.ts` plus its test, a permission-floor test, and a smaller `will-attach-webview` body in the shared file.
</objective>

Add one test that walks the hardened output and asserts every one of the nine invariants in a single pass, so the failure message names which invariant regressed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer-supplied webview attributes to main | The renderer asks for a guest with given webPreferences, partition and src; main overrides all three |
| guest page to Chromium permission prompts | Untrusted page content requests capabilities there is no UI to evaluate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-11 | Elevation of Privilege | `will-attach-webview` guest hardening | high | mitigate | The nine invariants move to `hardenGuestWebPreferences` with a test that fails when any one is removed, and the function takes no override parameter, so there is no supported way for a caller to request a weaker guest. |
| T-06-12 | Elevation of Privilege | guest `src` scheme | high | mitigate | Any src that is not http or https is rewritten to `about:blank`, tested against `file:`, a custom app scheme, `javascript:`, and a missing value. This is the control that stops page content driving a local file read. |
| T-06-13 | Information Disclosure | session partition | high | mitigate | `params.partition` is pinned to `GUEST_PARTITION` regardless of what the renderer asked for, so third-party cookies and storage never reach the app session holding the user's GameBanana login. Tested. |
| T-06-14 | Elevation of Privilege | Chromium permission requests from guest pages | medium | mitigate | Characterization test pins the blanket deny with the single fullscreen exception across both the request and the check handler, so the capture work cannot widen it unnoticed (D-12). |
| T-06-15 | Tampering | duplicated hardening logic | medium | mitigate | Exactly one copy of the assignments exists after the extraction, so a future edit cannot fix one copy and miss another. Acceptance criteria assert `electron/main/index.ts` holds a call, not a copy. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No packages are added by this plan. RESEARCH.md's Package Legitimacy Audit records zero new dependencies, so there is no install task to gate. |
