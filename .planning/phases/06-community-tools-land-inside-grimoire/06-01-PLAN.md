<assumption_delta_decision>
**Transition detected:** `SHORTCUTS` in `src/pages/Browser.tsx` is a flat `{ label, url, nsfw? }[]` whose entries are undifferentiated bookmarks. This phase makes one of them capability-bearing, which turns a homogeneous list into a typed set.

**Noun that becomes primary:** the destination *kind*. A catalog entry's identity is now "what sort of destination this is", not "a URL with an optional adult flag".

**Decision: promote.** `kind` becomes the entry's primary discriminator and is required on every entry (no optional, no default). `nsfw` stays exactly as it is, a secondary orthogonal boolean, because it answers a different question (should this be shown) than `kind` does (what can this do). This confirms the reading CONTEXT.md D-04 already recorded.

Rationale: the alternative, `add-alongside`, would leave `kind` optional and force every consumer to handle an undeclared entry, which is precisely the "hardcoded array that rots" failure the phase goal names. Making `kind` required means adding a destination without deciding what it is fails at the type level.

Accepted consequence: `BrowserDestinationKind` is a closed union. Adding a fifth kind later is a type change plus a group-header copy key, not a migration. That is cheap and reversible.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest `<webview>` page to Chromium download manager | Arbitrary third-party page JS decides to start a download; the bytes are entirely attacker-chosen |
| Chromium download manager to main process (`will-download`) | The only place Grimoire can decide whether a download is captured or handed off |
| main process temp file to `import-custom-mods` | An untrusted byte stream crosses into the mod library here |
| renderer to main (`browser:set-active-destination`) | The renderer asserts which destination is current; a compromised renderer could lie |

## STRIDE Threat Register

| T-06-01 | Tampering | `will-download` handler, `electron/main/services/browserDownloadCapture.ts` | high | mitigate | Capture requires renderer-pushed `kind === 'tool'` AND live guest origin equal to the pushed origin (`shouldCaptureToolDownload`). Every other case keeps today's `preventDefault` plus `openExternalSafe` (D-11, D-12). Unit tested against a redirect-away case. |
