<objective>
Turn the rigged hero preview from an arithmetic estimate into a release decision.

Purpose: `docs/rigged-preview-spike.md` section 6 produced a frame-budget figure by arithmetic and labelled it as one. Section 9 says outright that no fps measurement exists and that check 3 of section 8 is the blocker on defaulting the rigged path on. Section 9's next step 1, decoupling rigged from cloth, already shipped: `heroPoseRenderFeatures.ts` gives rigged its own flag and `HeroPoseViewer.test.ts` asserts the decoupling. Next step 2 is this plan.

A `checkpoint:decision` is used here because the input is a measurement only a person with a GPU and a running build can take, not because the decision is hard to undo. Flipping a module constant behind an already-decoupled flag is a one-line, fully reversible change: no on-disk format, no published contract, no dependent system.

Output: `RELEASE_RENDER_FLAGS.rigged` set to what the measurement argues for, the recommendation written into `docs/ingame-verification-record.md`, and the spike's own next-step list marked resolved.
</objective>

| Boundary | Description |
|----------|-------------|
| human measurement -> release flag | A frame-time reading taken by a person changes what shipped builds render |
| game pak file -> vpkmerge sweep | A user-supplied path is passed to a bundled native tool on the ship branch |
| record doc -> git history | The measurement and the recommendation become the project's justification for the flag |
