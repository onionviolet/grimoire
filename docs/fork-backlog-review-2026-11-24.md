## Chat Wheel

**F1. Make inactive states safe.** The experimental switch currently gates the editor. A fresh save allocates an enabled VPK. Picking a saved wheel in the editor tells the user which file they are editing, while the game's actual wheel depends on the mounted VPK and saved game bindings. The removal dialog covers deletion from Chat Wheel and Installed. The native build assigns custom option IDs by list position, beginning at 70. Deleting a menu can remove an ID or shift the meaning of a later ID. The compiler accepts more commands per menu than the game's documented twelve, so successful conversion alone is an insufficient install check. [Save handler](../electron/main/ipc/chatWheel.ts) · [Converter](../electron/main/services/chatWheelNative.ts) · [ChatLane limitations](https://github.com/RedMser/ChatLane#known-bugs-and-limitations)

**A1. Separate draft, export, and activation.** Save and export without touching Deadlock. Keep fresh drafts free of game bindings. On activation, show the winning provider of `scripts/ping_wheel_messages.vdata_c`, allow a single managed active wheel, and surface external VPKs that provide the same resource. Stage and validate the artifact, then use the existing mod mutation and recovery machinery to replace it and its metadata together. Keep what is being edited and what can actually load in game visible. Preserve the original YAML in all paths.

**A2. Guard transitions that can strand a binding.** Review disable, delete, menu deletion or ID-changing edits, profile switching, isolation, and vanilla launch against the same rule at the mutation boundary. Include imported VPKs identified by their contents, since the current UI predicate identifies wheels by metadata. Keep the existing wheel available while the user clears custom bindings. If binding state cannot be read reliably, require an explicit guided unbind step before removing the provider. When a patch or an outside launch resets mounts, explain how to restore the known-good provider where compatible and offer an out-of-game-accessible recovery card with the documented console fallback. Verify that fallback on the current build and preserve stock slots where possible. Avoid automatic edits to Steam-synced state until its format, account scope and persistence are demonstrated. [Current removal coverage](chat-wheel.md#removing-a-wheel) · [ChatLane recovery procedure](https://github.com/RedMser/ChatLane#known-bugs-and-limitations)

First acceptance run on the current game build: open Settings and the stock wheel with a draft only. Activate one custom menu and bind it in game. Exercise normal launch, disable or an ID-changing edit, a profile change and a vanilla launch. Finish by simulating missing mounts in a disposable setup, recovering, then safely unbinding and removing the wheel. Prove Settings and the stock wheel still open after restarting Deadlock. Grimoire can guard its own launch and mutation paths. A Steam-only launch after an external reset needs game-side evidence before it can carry any guarantee.

**A3. Finish parity by testing the player workflow.** Grimoire already has both override maps, menu names and icons, drag and keyboard reorder, a radial preview, and native converter fixtures. Add direct VPK export, command audition where an exact audio match exists, and preflight diagnostics for oversized menus, ignored or unavailable commands, and the known team and slot limitations. Compare the pinned command table and option IDs with the current base resource. Verify both teams and representative parent slots. Consider stock-command-only named presets as a lower-risk experiment. Test modifier release order and restoration before offering in-match switching. Keep profile-driven custom wheel swaps behind the binding work. [Current editor](chat-wheel.md) · [Preset idea](feature-followup-2026-11-23.md#community-ideas-that-extend-existing-features)

## Foundry Sound

**A4. Make one replacement easy to finish and verify.** The import editor already has a waveform, draggable trim, selection playback, gain and RMS matching. Add exact keyboard trim and waveform zoom, quick stock versus edited A/B at a consistent monitor level, and a peak/clipping indicator that reflects the built result. Keep preview volume distinct from baked gain. Show the exact event, target path and winning provider, then let the user audition the staged or rebuilt bytes through the same flow. A short ability cue and a longer voice clip make useful fixtures. Test preview versus the built VPK for duration, loudness and any loop settings. Add fades once preview and mint can share their semantics. [Sound editor](../src/components/foundry/SoundImportEditor.tsx) · [Sound Locker ownership](sound-locker-plan.md)

Once single-event editing is reliable, add folder-to-hero voice replacement. Match filenames to exact events, show missing and ambiguous matches, audition a few rows, and stage one reviewed build. Keep existing shuffle pools and the build tray as owners. A separate full audio workstation would add scope without improving that first replacement.

## Implementation follow-through

Chat Wheel now separates draft save, VPK export and activation. Activation uses a recovery journal, checks competing providers and reviews changes to existing custom menu IDs. The main process recognizes imported providers by resource path. Disable asks for unbind confirmation. Delete, profile restore, isolation and vanilla launch guard against removing an enabled provider that could leave a binding behind. Chat Wheel and Recovery show known mounts, installed option IDs and ChatLane's documented console fallback. [Chat Wheel guide](guide/chat-wheel.md)

Foundry Sound adds keyboard trim, waveform zoom, stock comparison and a peak estimate for the selected audio after gain. Its Voice browser can review a folder by exact clip or single-clip event name, audition candidates and stage unique matches as one tray item. Duplicate claims and unmatched files stay visible and are skipped. [Sound editor](../src/components/foundry/SoundImportEditor.tsx) · [Batch staging](../src/components/foundry/VoiceBatchStaging.tsx)
