# Sound Forge assessment

November 24, 2026. Grimoire v1.35.2 candidate source at `5160f671`, with a separate check of the November 23 Windows package's binaries against the locally installed Deadlock assets.

Sound Forge has a capable audio editor and a working VPK engine. The main Door Stuck workflow stages a sound edit in the build tray, where it can be exported or installed as a local mod. The weakest link is what happens around install and rebuild. The direct sound handler has a file-copy bug, and the tray does not confirm which installed provider will actually win. Current-game playback still needs acceptance.

| Workflow | Evidence |
| --- | --- |
| Find and audition | Hero ability, voice and global catalogs, stock and installed-source audition, and searchable annotations are wired. The local engine read the current hero, voice and global catalogs. |
| Edit and stage | The editor has waveform zoom, keyboard trim, stock A/B, RMS matching, gain, a peak estimate and loop settings. Pool choices include selected targets, mapped files and a seeded library. Voice folder import stages unique matches and shows skipped files. |
| Build and export | The tray checks source paths and reviews exact output paths and collisions within the tray. The build verifies the actual VPK entries against that review. The native engine built and read back real Deadlock clips. |
| Install and manage | Tray installation copies the VPK and records provenance for My changes. The direct sound-swap and legacy retune route has a separate broken install path. Current-candidate app installation and in-game playback were outside these checks. |

## Recommended order

1. **F1. Fix direct re-forge and test the install transaction.** The direct handler allocates a slot and hashes the destination without copying the built VPK. My changes sends legacy sound rebuilds through that handler, and its request also lacks the conflict resolution the handler requires when the existing mod claims the same clips. The `replace-managed` choice validates ownership without replacing the prior output. Share the existing safe installation path and define replacement as an actual, reversible operation. Test the real IPC with a disposable library and assert the installed bytes, metadata and rollback after a failed conflict change. [Direct handler](../electron/main/ipc/mods.ts#L1985) · [Legacy rebuild caller](../src/components/foundry/MySoundChanges.tsx#L116) · [Tray install](../electron/main/ipc/mods.ts#L2174)
2. **F2. Review the final provider and the blast radius.** The single-sound stage flow checks installed owners early, while the tray's final confirmation covers source files and collisions among staged edits. Folder staging can enter the tray without that early installed-owner check. Show installed contenders, the predicted winner and any unreadable scope at install time, then revalidate on commit. Also show stock events that share each target. The current catalog maps both `Hornet.Assassinate.Charge.Complete` and `Priest.Witching.Hour.Cycle.Stop` to `sounds/abilities/priest/priest_witching_hour_cycle_stop_04.vsnd`. An in-place override changes both references. Warn first, then investigate an event-scoped replacement with a unique clip path where soundevents precedence is understood. [Sound staging](../src/components/foundry/SoundBrowse.tsx#L1255) · [Folder staging](../src/components/foundry/VoiceBatchStaging.tsx) · [Tray confirmation](../src/components/foundry/FoundryBuildTray.tsx#L79)
3. **F3. Make rebuild inputs durable.** Use Original re-resolves the game clip when staging, then records the extracted cache file in the assignments. A later patch and cache refresh can prune it. Persist the stock clip ID and game fingerprint and resolve it at build time. If the stock source has changed, show that before reusing trim and gain. For imported clips, let users relink missing files and preview the result before committing the rebuild. [Original source resolution](../src/components/foundry/SoundBrowse.tsx#L1224) · [Voiceclip cache](../electron/main/services/foundryCatalog.ts#L707) · [Build provenance](../electron/main/services/foundryForge.ts#L58)
4. **F4. Let the user hear the generated VPK.** Keep fast editor playback and add an on-demand audition of the baked `.vsnd_c` in the tray or My changes, alongside stock and the applied provider when available. Show measured output duration, peak and loop status. The editor operates on decoded samples and the engine trims on MP3 frame boundaries, so the exact edit fields and peak estimate cannot describe the final bytes by themselves. [Editor](../src/components/foundry/SoundImportEditor.tsx) · [Mint path](../electron/main/services/foundryCatalog.ts#L269)
5. **A1. Give release acceptance a small sound matrix.** In an isolated packaged profile, use the normal UI to build and install one trimmed ability cue, a small voice folder and one looping global sound. Include a competing third-party sound VPK. Confirm emitted paths, installed winner, cues in a private current-game session, and successful rebuild and removal. Refresh the [player guide](guide/door-stuck-sounds.md) with the proven flow. Its MP3-only, replace-all and zero-test claims predate the current implementation. The authoritative publication gate remains the hosted Windows, Linux and macOS package-and-smoke matrix for the final release commit. ## Checks run

- 104 tests passed in 18 targeted Vitest suites. These cover editor behavior, pooling, batch matching, annotations, conflict analysis, build review, provenance and conversion. The editor uses a fake Web Audio stack and the build tests mock the mint step, so these are targeted component and service checks.
- The Windows vpkmerge 0.30.1 (`c34fadf`) CLI extracted a Vindicta voice line, minted it into a VPK, merged it with a trimmed ability cue and extracted both exact target entries. The re-extracted voice MP3 was byte-identical to its stock input.
- The November 23 package's FFmpeg converted a synthetic two-second WAV with the app's conversion arguments. The packaged vpkmerge minted five Assassinate cast clips and inherited looping for `Music.Base.Attack`. A separate ability build requested a 150 to 800 ms selection and -6 dB gain. Its extracted MP3 decoded at 676 ms, with mean level -30.9 dBFS versus -24.1 dBFS for the donor. This illustrates the difference between editor values and the encoded output for one fixture.
- The native checks ran directly against binaries and wrote only to temporary directories, which were removed. They did not exercise renderer-to-main install, the active mod library, or in-game playback. The findings above describe the checked source and native behavior.

## Implementation follow-through

- **F1.** Direct sound installs and tray installs now copy and register under the mod mutation lock. Rebuilding an enabled sound mod uses its existing load slot and parks the previous VPK disabled. A failed install restores the previous VPK to its original slot.
- **F2.** Review shows the expected provider and lists installed contenders and known stock events sharing each path. Install checks the reviewed state again before committing. Voice folder matches and tray rows can be selected independently. Completing a build removes only its included edits. Parry sounds enter the same build tray.
- **F3.** Stock sources retain a clip identity and game-build fingerprint. The engine resolves the sound at build time and rejects a changed fingerprint. Rebuild can use the current stock clip after confirmation. Missing imported audio can be relinked in the tray and during rebuild.
- **F4.** Review can mint and extract the winning assignment for a selected path, report decoded duration and peak, and show the engine’s loop result. Stock and the current installed provider are available for comparison.
- **A1.** An isolated Windows x64 package using Electron 44.10.1 and fork vpkmerge 0.30.1 exercised WAV selection, staging, clear/select-all, baked playback, install, and a reversible tray rebuild. Additional IPC checks used current Deadlock assets to confirm the shared hero events, a competing priority-folder VPK, stale-review rejection, a trimmed one-shot preview, direct voice install, rollback after an injected file-copy failure, rebuild, removal, and stock refresh after a fingerprint change. The review was checked in dark and light. Current-game playback and the hosted release matrix remain open. [Updated player guide](guide/door-stuck-sounds.md)

Final source checks passed typecheck, UI, i18n and the production build. Node 24 Vitest passed 7,164 tests with 29 skipped using six workers, a 15-second timeout and one retry. Lint reported 114 warnings and zero errors.
